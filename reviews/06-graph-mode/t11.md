Written after the fact, and the record says so: T11 reached main inside
an unrelated pull request — a fix branch cut from this feature branch
rather than from main — and was reviewed there. The review found five
blocking defects, which is what that shortcut cost.

The worst was mine and it was on main: the check for a failed turn
grepped `"is_error":true` across the whole stream, and that field
belongs to every failed tool result as well as to the result record.
Red-then-green is what a Keeler task *is*, so every honest task would
have reported `died` with its gate never run — a false death, worse
than the false pass it replaced, because it also invites resuming
finished work. The check is scoped to the result record now, and the stub
agent emits what the real binary emits: a failing tool result, then a
clean result.

The board exited non-zero whenever its last task was not died, because an
AND-list's status becomes the loop's. keeler-resume re-ran done tasks,
passed an unquoted path to tmux and silently no-opped on any path with a
space, started sessions without a worktree to run in, and did not check
for tmux at all. The runner heredoc executed its own comments: backticks
in an unquoted heredoc are command substitution, so every spawn printed
"command not found" and the artifact lost the words it was documenting.

Four guards survived hand-mutation before this commit; each has a test
that fails without it now. The reviewer's own probes against the real
binary settled what the design rested on: --verbose is mandatory with
stream-json, the result record cannot be forged from agent text because
tool output is JSON-escaped, and subagents emit no nested result.

Also fixed: keeler-land left .stream behind, keeler-resume was not in the
installed recipe list, neither shipped doc named it, and the spec's
Implementation Notes had been spliced mid-paragraph and promised three
things while listing two.
