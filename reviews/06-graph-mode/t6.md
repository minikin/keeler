## What the conformance pass found (fixed in 94dfee9)

- `git worktree list --porcelain | grep -qxF …` — `grep -q` closes the
  pipe on its first match, and under `set -o pipefail` a producer killed
  by that SIGPIPE makes the pipeline non-zero, so the `|| continue`
  would silently skip a worktree that *is* registered. Reproduced with a
  large producer (status 141). grep drains its input now.
- A worktree that will not go — locked, or on a disk that is gone —
  ended the run with a raw git error *after* the baseline and the spec
  were staged. It is named and stepped over now, and the next task is
  still cleaned up.
- The success line claimed the branch was deleted whether or not it was.

## What the code review found (all five fixed in 21f3807)

1. **`git branch -D` destroyed unmerged work.** A landed task's branch
   was force-deleted whether or not its commits had reached main;
   reproduced with a branch carrying one never-merged commit, which
   survived only in the reflog. The branch must now be contained in
   `HEAD`; when it is not, the worktree and the branch are left in place
   and named, with the two-command line that finishes the job — because
   a squash merge looks exactly like unmerged work from here, and the
   safe default is to leave it and say so. `-d` replaces `-D`: after
   that check the safe delete is the one that can succeed.
2. **Nothing checked the worktree was still on the task's branch.** A
   human who switched it to a fixup branch left the task's branch
   standing elsewhere, and cleanup deleted it anyway.
3. **The spec loop read the working tree.** An uncommitted tick marked a
   spec `Implemented` and deleted worktrees — readiness from a file in no
   commit, which is exactly what `keeler-spawn` refuses. The same guard
   fixes the fourth finding.
4. **`git add -- "$spec"` staged the whole file**, sweeping unrelated
   uncommitted edits into the commit the human is told to review as the
   baseline and the Status: line.
5. **Cleanup left the run's verdict behind**, and `keeler-status` reads
   the verdict before the graph: the board printed `passed` beside the
   path of a worktree the land had just removed. The verdict and the
   runner go with the worktree; the log stays, being the only record of
   what the run said.

Also from that review, and fixed with it: `*Approved*` matched
`TEMPLATE.md`'s `Draft | Approved | Implemented` menu — the Status:
line's *value* must be `Approved` now — and the mark is a copy-then-move
rather than a truncate-then-write, so a land stopped mid-write cannot
leave a spec empty. That last one is right by construction rather than
by a test: the race is not reproducible from outside the process. What
the tests do pin is that the spec keeps its own permissions and that no
temporary file is left beside it.

The reviewer confirmed as sound: the SIGPIPE reasoning above,

## Found in code this task did not write, reported upward

`scripts/keeler-graph.sh` (T1's, as amended by `54c01fd`, which this
branch inherited) truncates a Tasks section silently, and that is a
correctness risk for T6 in particular: a graph that loses its tail
reports every *visible* task as done, and `keeler-land` would then mark
a spec `Implemented` while real tasks are unfinished. Two shapes, both
reproduced against the script as it stands on this branch:

- a sub-heading inside the section (`### Phase 1`) ends it — the whole
  spec parses as zero tasks, exit 0, empty report;
- a `#` comment inside a fenced example inside the section ends it, the
  heading rule being evaluated before the fence rule — everything after
  the fence vanishes.

Neither is T6's to fix. The land side could refuse a spec whose report is
empty while the file plainly has checkboxes; that is a spec amendment
rather than a silent addition, so it is left for the human.

Also inherited, and reported rather than touched: `keeler-status` checks
the exit file before the graph, so a task that landed after a failed run
reads `failed (exit N)` forever. T6 removes the verdict of a task it
cleans up, which fixes the case it creates, not the general one.
