## What the code review found

Six findings; the review read the whole branch, not only this task.

1. **A spec that quotes the format was parsed as the quotation.**
   (`scripts/keeler-graph.sh`, fixed in c826c09.) Fences were tracked
   only once the Tasks section had opened, so a fenced `## Tasks` in a
   spec's Context — the shape of every spec that documents the format —
   opened the section there. Reproduced: the example's one ticked task
   became the whole graph and the real section was never reached. The
   consequence is the worst one this parser has: `just keeler-land`
   reads every task as done and stages `Status: Implemented` on a spec
   whose tasks were never started. Fences are tracked file-wide now,
   before any rule reads a line.
2. **A fence left open swallowed every task after it, in silence.**
   (Fixed in c826c09.) Reproduced: T1 ticked, an unclosed fence, T2 and
   T3 below it → the report was `T1 done`, exit 0. This is the failure
   the script's own comment names — "a graph reporting fewer tasks than
   exist reports every one of them done". It is refused now, naming the
   line the fence opened on.
3. **An ordinary markdown link bullet was refused as a malformed
   checkbox.** (Fixed in c826c09.) `- [the design note](notes/design.md)`
   in the Tasks section exited 1, and a refusal is total: one link blocks
   the graph, the spawn, the board and the land for the whole spec. A
   `](` is a link, not a checkbox; the guard still catches every
   checkbox shape the grammar cannot read.
4. **The routing check was narrowed too far.** (Fixed in c826c09.) A
   detour added as a sub-bullet or a wrapped continuation of a numbered
   step does not begin with a digit, so it would have passed. The check
   reads the whole stage list now — planted a sub-bullet detour (fails)
   and a paragraph of prose after the list (passes).
5. **`keeler-spawn` computes readiness from main but cuts the worktree
   from HEAD.** Left open. Run from a branch whose copy of the spec
   differs from main's, the spawned agent reads a spec that is not the
   one readiness was computed from. The guards that exist cover the
   working tree against HEAD and the spec's absence from main, not this
   third case. It is T3's behaviour and the Implementation Notes do not
   say which side should win, so it wants the user's decision rather
   than a change made here.
6. **`keeler-status` reads the working-tree spec** while `keeler-spawn`
   refuses an uncommitted one and `keeler-land` refuses a spec that
   differs from HEAD. Left open, same reason: a board showing live
   local state is defensible, but an uncommitted tick makes an unmerged
   task print `done` and suppress the log and worktree a resume needs.
