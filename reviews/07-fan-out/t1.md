**Resolved after the fact, by a human.** Two of the six scenarios could
not be finished by the spawned agent, and the text they needed was
written into the run's summary rather than into the files; the human
pasted it in, and all nine tests are green. The finding below stands as
the reason that was necessary.

Two of the six scenarios cannot be finished by a spawned agent. Their
deliverable is `.claude/commands/keeler/spec.md`, `.claude/keeler.md` and
`.claude/commands/keeler/feature.md`, and every attempt to write those
files was refused: they are agent-instruction files, and this harness
requires the human's explicit permission for each one — which a headless
session has nobody to ask. The tests for them are written and red, and
the text they want is in the run's summary. Four tests pass, four fail,
and every failure is that one refusal.

That is worth recording as a hole in graph mode rather than an accident
of this task: any Keeler task whose deliverable is a command file or the
rules file cannot be done by `keeler-spawn`, because the permissions the
spawn grants — `Bash(cargo:*)`, `Bash(just:*)`, `Bash(git:*)`, edits
under `acceptEdits` — do not include the sensitive-file consent those
paths need. In this repository, where `.claude/*` *is* the product, that
is most tasks of most specs.

Review found four defects in what was written, two of them real:

- A new spec `git add`ed but never committed was asked of the index
  (`git ls-files --error-unmatch`) rather than of HEAD, so
  `git checkout HEAD -- <it>` failed on a pathspec HEAD does not know and
  `set -e` ended the run before any branch was cut. That is the ordinary
  state of a spec `/keeler:spec` has just written. Fixed, with a test
  that fails without the fix.
- `git rev-parse --show-toplevel` answers physically and a shell's `pwd`
  answers logically, so a repository reached through a symlink — /tmp on
  macOS is one — had its own spec refused as "not inside" it. `pwd -P`,
  with a test that runs the recipe through a symlink with `PWD` set the
  way a shell sets it.

Two were declined, with reasons:

- `KEELER.md` documents `just keeler-fan-out`, which lands in T2 and T3.
  That is the spec's own ordering: the scenario _The rules describe the
  fork and the wave_ belongs to T1, and the recipe to T2. The documents
  are ahead of the code inside this feature branch and level with it at
  fan-in.
- The branch is cut from HEAD while `_main-ref` supplies only the name to
  compare against, so a stale local `main` is cut from rather than
  `origin/main`. That is `keeler-land`'s behaviour too, and cutting from
  a ref the human has not checked out would surprise anyone whose local
  main is deliberately behind. Left as it is, deliberately.

Noted, not this task's: `keeler-spawn` builds `spec_abs` the same logical
way and has the same symlink defect. T2 lifts that block out into
`_spawn-preflight` and is where the fix belongs.

The mutation gate measured nothing — the deliverable is shell, markdown
and tests, and `src/` did not change — which the run says rather than
reporting a pass over nothing.
