## Part 1 — spec conformance

T4 has one scenario, _The wave is one tmux window with a pane per run_,
and its three clauses are three tests plus two that hold up the first:

| Clause                                                                 | Test                                                              |
| ---------------------------------------------------------------------- | ----------------------------------------------------------------- |
| a session `keeler-<spec-slug>-wave` with a pane per spawned task, each attached to that task's session, laid out so all are visible | `the_wave_is_one_tmux_window_with_a_pane_per_run`                  |
| `tmux attach -t =keeler-<spec-slug>-wave` shows it, and the run prints that — or `switch-client` from inside tmux | `the_run_prints_the_command_that_shows_the_wave`                    |
| the per-task sessions still exist, so `keeler-status` and a single attach work as before | `the_per_task_sessions_outlive_the_view_and_the_board_still_reads_them` |
| the whole thing, against a real tmux server                            | `a_real_tmux_wave_is_a_window_with_a_client_on_every_run` (`#[ignore]`d) |

Clause by clause:

- "a tmux session named keeler-<spec-slug>-wave holds one pane per task
  that spawned, each attached to that task's session" — the stub records
  the session created with `-s keeler-42-fixture-wave`, and the pane
  commands of the three `split-window` calls are asserted equal, in the
  wave's order, to the three task sessions. Each pane runs the attach
  through `.keeler/runs/<slug>/wave.sh`, which is asserted to exist, to
  clear `TMUX=` and to hold the exact target — and no pane command
  carries a `=` of its own, which is the reason the runner exists: the
  pane runs under the user's shell, and in zsh `=name` is a command
  lookup.
- "laid out so all are visible" — the call sequence is asserted exactly:
  split, tile, split, tile, split, tile, and one more tile over the room
  the window's own pane gives back.
- "`tmux attach -t =keeler-<spec-slug>-wave` shows the wave, and the run
  prints that command — or `switch-client` when it is already inside
  tmux" — both, from two runs that differ only in `TMUX` being set. The
  printed target is quoted (`'=keeler-…-wave'`), as `keeler-resume`
  already quotes its own: unquoted, a zsh reading the line back would
  look `=keeler-…-wave` up as a command. The test asserts the command and
  the exact target, not the quoting.
- "the per-task sessions keeler-<spec-slug>-<task> still exist, so
  keeler-status and a single attach work exactly as before" — the three
  sessions are asserted started in order, and `just keeler-status` is run
  twice against the same project: with the three alive it says `running`
  for each, and with only the view alive it says `running` for none. The
  second half is the prefix hazard the Implementation Notes name, tested
  from the other side.
- "one test marked `#[ignore]`-unless-real-tmux runs the true thing" —
  `a_real_tmux_wave_is_a_window_with_a_client_on_every_run` runs the wave
  against a real server on a socket of its own (`TMUX_TMPDIR` under
  `/tmp`, because a unix socket path is capped near 104 bytes and a macOS
  temporary directory spends most of that), holds each stubbed turn open
  for 20 seconds, and asserts every run's session has a client of its own
  and the view is one window of three panes. It kills the server and
  removes the socket before it asserts anything, so a failure leaves
  nothing behind.

Two more tests are not clauses but are what makes the first clause true
when something goes wrong; both are named for what they hold:
`the_window_is_built_in_a_pane_of_its_own_which_does_not_stay` and
`a_view_tmux_will_not_build_is_said_and_not_counted`. See findings 3 and
4 — they arrived as fixes.

Scope: the diff is `keeler-fan-out`'s tail and `tests/fan_out.rs`.
Nothing else in the Justfile moved, no command file changed, no document
changed — T4's deliverable is "the window, and the attach line the run
prints", and that is what is here. The three tests whose session counts
the view changed (`yes_spawns_…`, `a_refusal_mid_wave_…`,
`the_yes_does_not_travel_…`) now read the task sessions through
`task_sessions()`, which filters the view out; the yes is asserted absent
from all four sessions rather than three, since the view's panes inherit
its environment too.

Invariants: T4 states none of its own. T2's property — the wave printed

## Part 2 — generic review

Run through the built-in `code-review` skill at high effort over the
branch's diff. Four findings; the two in the Justfile were T4's and are
fixed in `02aac36`, and the two in `.claude/keeler.md` are not T4's.

### Finding 1 — the view was anchored to the first run's pane (fixed)

`keeler-fan-out` created the view session with the first task's attach as
its only pane. A pane closes when its command ends, and the last pane
closing takes the session with it — so a run that ended in the second it
took to lay the wave out destroyed the window, and every `split-window`
after it failed, leaving the runs still going with nothing to be shown
in. This is not hypothetical: the first real-tmux run of this branch
failed exactly so, `can't find pane: =keeler-42-fixture-wave`.

Fixed: the window is built in a pane of its own — `new-session -d -P -F
'#{pane_id}'` with no command — one `split-window` per run into it, and
that pane killed once the runs have theirs, or the session killed if
none of them got one. `the_window_is_built_in_a_pane_of_its_own_which_
does_not_stay` pins the shape, and the real-tmux test pins the result.
It also reads as the Implementation Notes describe it: "one
`split-window` per spawned task".

### Finding 2 — the file writes ran under `set -e` (fixed)

`mkdir -p`, the heredoc that writes the runner and `chmod +x` were
unguarded, so a read-only `.keeler/` or a full disk ended the recipe
*after* the wave had spawned: no `spawned …` line, no `board:` line, no
`refused …` line, and exit 1 — the opposite of the recipe's own claim
that a view that cannot be built leaves the exit code alone. Fixed: they
are a function whose every step is tested, and the view is skipped when
it fails. Two tests hold the invariant from both sides — a tmux that
refuses to split, and a runner file that cannot be written; both assert
the wave still spawned, the run still reported it, and the exit is zero.
