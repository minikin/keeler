## Findings (settled)

1. `backlog.rs:253` — the panic-freedom property never generated a second
   line. `string_regex(".{0,80}")` uses regex-syntax defaults, where `.`
   excludes `\n`, so all 512 cases held at most one entry: the duplicate
   branch — the parked gate's original blocker, and the reason this
   property exists — was never reached, and `if false` in place of the
   duplicate check would have left the suite green. Fixed in f088136:
   the property now builds a file from lines drawn from the same small
   universe as the addresses, and checks each answer against that file —
   a parse smuggles no duplicate through and drops no line; a refusal
   names a line that exists, quotes what that line says, and for a
   duplicate points at an earlier line holding the same address.
2. `backlog.rs:62` — the duplicate refusal named the later line and
   quoted its text, but not the earlier line. Because two spellings of
   one address are one task (`06-graph-mode/T1` and `06-graph-mode/t1`),
   the quoted text need not appear on the line it duplicates: the
   module's own test input was a case where grepping the message finds
   only one of the pair. Fixed test-first in f088136 — `Duplicate` now
   carries `first`, and the message reads `line 3 duplicates line 1`.
3. `backlog.rs:75` — `entry` accepted any half free of `/` and
   whitespace, so a hand-edited `01-install/t1,` parsed into a well-formed
   `TaskId` that no ticked task can equal. The gate would then report
   `01-install/t1` missing while `BACKLOG.md` plainly listed it, with no
   refusal pointing at the line that lied — the failure mode this module
   exists to prevent, arriving silently. Fixed test-first in f088136:
   each half must be ASCII letters, digits, `-` or `_`, the way every
   spec slug and task id in this repository is spelled. Pinned by
   `an_address_wearing_prose_is_refused_rather_than_silently_accepted`
   over a bullet, a comma, a full stop, backticks and brackets.

## Open question for T5 (no code change here)

is what the spec asks for ("one task per line as `<spec-slug>/<task-id>`")
and what finding 3 tightens. It follows that `reviews/BACKLOG.md` can
carry no Markdown heading and no comment explaining what the thirty-nine
are, though its name ends in `.md`. That is T5's problem to hit, and the
answer is a spec amendment (allow `#` comment lines) or a file that is a
bare list with its explanation living in CONTRIBUTING. Recorded here
rather than fixed, because inventing a comment syntax the spec does not
mention would be scope creep in the one module whose job is refusing
lines it was not told about.
