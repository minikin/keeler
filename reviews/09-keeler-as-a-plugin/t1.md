`install.sh` loses exactly what the spec names — the `install_file` loop,
the rules block, the `CLAUDE.md` block, the justfile-collision scan — and
keeps tools, `clippy.toml`, `rustfmt.toml`, the `Cargo.toml` and
`.gitignore` edits and the workflow. `--no-ci` is wired through argument
parsing, the usage text and the header comment. The conflict convention,
the `free_name` behaviour and the symlink boundary are untouched and
still pinned by their own tests, retargeted onto files that still land.

**Review found four defects; three fixed here, one left to the task that
owns it.**

Three were the same shape: a file leaving the install set left a check
asserting nothing, silently.

- `a_file_installed_empty_is_caught` truncated `.claude/keeler.md`, which
  nothing creates any more. The defective wrapper died on the
  redirection, the checker refused at "installer exited non-zero", and
  bash's own error text happened to contain `keeler.md` — so the test was
  green for the wrong reason and `integration-check.sh`'s "landed, but
  not with Keeler's content" branch was covered by nothing. It truncates
  a tool config now.
- `integration-check.sh` kept three `.claude/keeler.md` exemptions from
  when the installer replaced that file wholesale. With the installer no
  longer touching it, the exemption excused a clobber: an installer that
  rewrote an adopter's own copy was waved through while every other
  clobber was refused. Removed, with the `.bak` allowance.
  `an_upgrade_over_an_older_rules_file_is_not_called_a_clobber` pinned
  the exemption and had become vacuous — replaced by
  `a_rules_file_left_by_an_earlier_install_is_the_projects_own`, which
  asserts the clobber is caught.
- `what_adopters_receive_describes_their_project_not_ours` scans the
  installed tree, now four files. The `Justfile` — the file the gate was
  written for, after a real leak shipped in it — lost its guard. Adopters
  reach the recipes through the plugin rather than through the install,
  so the recipes are now scanned where they live.

One is left open, deliberately, because another task owns it:

- **`templates/keeler.yml` breaks for every adopter between T1 and T12.**
  The shipped workflow runs `just lint`, `just test`, `just cov` and
  `just crap-delta` against the project, and its `branch-baseline` job
  fails outright when the project has no justfile — which, after T1, is
  every adopter. The spec assigns the rewrite to T12 (`Needs: T3, T10`),
  which adds the cache, the fetch and `just --justfile
  "$RUNNER_TEMP/keeler/Justfile"`. **This feature must not reach main or
  a release before T12 lands.** Nothing in T1 could fix it without
  writing T12's diff.

**Deviations from the task's stated file list.** T1's hot-file note names
`install.sh`, `tests/installer.rs` and `.github/workflows/ci.yml`. Two

  The rules and `CLAUDE.md` steps are deleted; the "every note names the

- `tests/wild.rs` — the spec says spec 03's checker "keeps working", and
  it does, but three of its *fixtures* named `Justfile` and
  `.claude/keeler.md`. One was red, two were vacuous.
