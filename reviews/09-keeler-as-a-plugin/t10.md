## Findings (settled)

1. **`mutants FILE` was broken for every caller.** The recipe read `$1`,
   which `just` does not set without `set positional-arguments`; the
   Justfile's own preamble says parameters arrive through the environment.
   Fixed to `$FILE` in 086f193. The scenario's assertion was flags-only,
   so it would have watched the recipe fail and reported nothing — it now
   also asserts the file reaches `--file`, verified red against a
   hard-coded name before being taken as green.
2. **A base that does not resolve left the gate green having measured
   nothing.** `from=$(git merge-base "$BASE" HEAD 2>/dev/null || echo
   HEAD)` fell back to the working tree, which in a CI checkout is clean,
   so `mutants-diff origin/main` in a shallow clone or a fork's pull
   request printed "No src/ changes — nothing was measured" and exited
   zero. This is the invocation T12 is about to put in the workflow.
   Fixed test-first in 1b66f00: a named base with no merge base refuses,
   naming the ref and `fetch-depth: 0`; pinned by
   `a_base_the_checkout_cannot_reach_is_refused`, which was red on the
   old body with exactly that message. The resolution moved above the
   intent-to-add block, so the refusal cannot leave entries in the index
   the recipe promises to restore.
3. **`[ "$BASE" = "HEAD" ]` cannot tell the default from an explicit
   `HEAD`**, while the comment above it read "Only when no base was
   named." The signature `BASE="HEAD"` is the spec's and is asserted by
   `tests/installer.rs`, and naming `HEAD` asks for the same comparison
   the default makes, so the behaviour is right and the comment was
   wrong. Comment corrected in 1b66f00.

## Findings (recorded, not acted on)

4. **`.cargo-mutants.toml` is still in this repository.** T10's task line
   says it is deleted once the flags carry it, and the flags do. It cannot
   go on this branch: `install.sh:212` still lists it in the `install_file`
   loop, which under `set -euo pipefail` aborts on a missing source, and
   `tests/installer.rs`'s `INSTALL_SET` asserts it lands. Both belong to
   T1, which owns `install.sh` and rewrites the superseded installer
   scenarios — and T10 carries no `Needs: T1`, so the graph allows this
   branch to run first. Deleting the file needs two lines T10 may not
   write. Left for whoever lands second: drop `.cargo-mutants.toml` from
   the loop at `install.sh:212` and from `INSTALL_SET`, then
   `git rm .cargo-mutants.toml`. Until then the file is inert
   duplication, not a disagreement — its eight settings and the eight
   flags are identical, and the tests assert the flags.
5. **`KEELER_COV_MIN` lets a task branch lower the coverage bar without
   the `branch-baseline` job seeing it.** True, and it is the spec's
   decision, not a defect: "The thresholds stay the adopter's", and the
   same spec has `branch-baseline` stop reading the project's justfile for
   a `cov:` recipe (T12). The bar is the adopter's to move, in their shell
   and in their workflow's `env:`; what the gates measure is still not
   theirs to change.
6. **An empty `KEELER_COV_MIN` is not the default.** `env()` falls back
   only when a variable is unset, so `KEELER_COV_MIN:` written bare in a
   workflow yields `--fail-under-lines` with no value. Not guarded: cargo
   rejects it loudly and the gate fails, which is the safe direction. A
   silently lowered bar would have been worth a branch here; a loud
   failure is not.
