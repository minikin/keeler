## Part 2 — generic review (`code-review`, high)

The shell was checked and is right: `\$PATH` survives the unquoted
`<<RUNNER` here-doc as a literal so the runner prepends to its own PATH
at run time, `$plugin_root` expands at write time so the path is baked,
and the prompt's `${CLAUDE_PLUGIN_ROOT}` passes through the recipe's
`\$` escape and the runner's quoted `<<'KEELER_PROMPT'` intact. Two
findings, neither a conformance gap, both needing a decision that is not
this task's to make.

1. **The prompt names a variable nothing in the spawned session expands**
   (`Justfile:521`). `${CLAUDE_PLUGIN_ROOT}` is expanded by Claude Code
   in a command file and set for hooks; in a `claude -p` prompt it is
   text. The agent's `Read` takes it literally and fails, and
   `--allowedTools` grants no `cat` to work around it. `keeler.md`
   reaches the agent anyway — the worktree has `specs/`, so the
   `SessionStart` hook prints it, which is the delivery the spec
   describes. `graph-mode.md` has no second route: the hook does not
   print it and no command file names it, so the spawned agent may never
   read graph mode's three rules for parallel branches.

   The spelling is the approved spec's, twice over: the scenario
   requires the prompt to name `${CLAUDE_PLUGIN_ROOT}/keeler.md` and
   `${CLAUDE_PLUGIN_ROOT}/graph-mode.md`, and the Implementation Notes
   repeat it. The fix — naming the resolved `$plugin_root` beside the
   variable, which the recipe holds three lines away — is behavior no
   scenario demands, so it is **proposed as a spec amendment** rather
   than smuggled in here.

2. **The chapter this task points the agent at names a command an
   adopter cannot run** (`graph-mode.md:33` and fourteen more lines).
   The table says the gate is `just keeler-branch`; this commit changed
   the prompt to `keeler keeler-branch`, and an adopting project has no
   justfile for the first spelling. The same stale `just keeler-*` is in
   `gates.md` and `keeler.md`. This was already open question 6 of
   `reviews/09-keeler-as-a-plugin/t4.md` and is owned by no task — T11
   is what makes it reachable by a machine rather than only by a human
   reading the repository. **T13** ("The documents follow") is where it
   belongs; it is raised again here because a spawned agent is now sent
   to read the file.
