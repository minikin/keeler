## Findings (settled)

1. **The rules chapter promised a check this task removed.**
   `graph-mode.md`'s first rule and `docs/KEELER.md`'s said CI refuses a
   `keeler/*` pull request whose diff touched `crap-baseline.json` *or the
   coverage bar in the `cov` recipe*. After this task the job guards the
   baseline and nothing else, and the recipe is not in the adopter's tree
   at all — so the sentence an agent reads before acting was false in its
   second half. No task in the graph owns those two files and no test
   pinned the sentence, so it would have shipped. Corrected in 15d19a3,
   and `the_branch_baseline_job_no_longer_reads_the_projects_justfile` now
   asserts neither chapter names the bar.
2. **The correction overclaimed in turn.** Its first wording said the bars
   "are not a file a branch can edit at all". They are: they live in
   `.github/workflows/keeler.yml`, which is in the adopter's repository,
   which a task branch can edit — and `pull_request` runs the branch's own
   copy of the workflow. Promising an enforcement nothing performs is the
   same defect as finding 1 pointing the other way. Both chapters now say
   where the bars are and that CI guards the baseline only (8f14ec8). That
   a branch can lower its own bar is a consequence of the spec's decision
   to move the bars into the environment, not a defect of this task; it is
   left open below.
3. **The YAML reader refused valid YAML.** A block sequence at its key's
   own column — `steps:` then `- uses:` at equal indent, the house style
   of half the workflows there are — read as an empty scalar and then
   errored "unexpected indentation". The scenario is a gate on a file
   GitHub parses, so a reader that fails a file GitHub runs is a gate that
   fires on the innocent. Fixed test-first in 8f14ec8: the positive half
   of `a_workflow_yaml_cannot_read_fails_the_gate` now carries a
   flush-style fixture, which was red on the old reader with exactly that
   message.
4. **The `just` finder saw only the head of a line.** Splitting a line on
   `&`, `|` and `;` and taking the first token missed `...; then just
   crap-delta; ...` — the one-line spelling of the CRAP gate this very
   workflow writes across four lines. The scenario would have gone on
   passing while the gate it names stopped covering the step. The finder
   skips leading shell keywords now, and the scenario asserts it on that
   exact line (8f14ec8).
5. **The mutation job's rationale tripped the mutation job's own
   assertion.** `!job.contains("cargo mutants")` fired on the comment
   explaining what a bare `cargo mutants` would have cost. An assertion
   that pushes out the rationale beside it is the wrong assertion: it
   reads non-comment lines now.
