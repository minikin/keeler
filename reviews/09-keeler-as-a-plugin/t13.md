## Findings (settled)

1. **The README promised a spawned agent the plugin, which T11 has not
   built.** The graph-mode section gained a sentence saying the runner
   passes `--plugin-dir`. It does not: the flag appears nowhere in the
   `Justfile`, `_write-runner` still emits the pre-plugin `--allowedTools`
   and a prompt naming `.claude/keeler.md`, and T11 is unticked and not
   among T13's `Needs:`. A document that describes the next task's work as
   done is the failure mode this whole stage exists to catch. Removed in
   13f57b9.
2. **The installer's manifest handling was described backwards.** The
   sentence inherited from the old README — it refuses "a `Cargo.toml`
   cargo cannot read" — is the opposite of what `install.sh:255-265`
   deliberately does: a project whose manifest cargo cannot parse yet (no
   sources) is installed into anyway, and the check at 328-340 fires only
   when the installer's *own* edits broke the file, restoring it. Restating
   an inherited falsehood is asserting it afresh; corrected in 13f57b9.
3. **The section reader cut the Install section inside its own example.**
   `section()` treated `# pin a release`, a shell comment in the section's
   fenced block, as a heading and ended the section there. The three
   assertions of the moment sit above the cut, so the test was green while
   reading two thirds of what it claimed to read — and the next assertion
   placed below the fence would have failed saying words were missing that
   are plainly there. It skips fenced blocks now and matches a heading as a
   whole line rather than a substring (`## Install` is also the opening of
   `## Installing from source`). The new assertion that the Install section
   still shows the `curl -fsSL` one-liner is below that fence, so it is red
   on the old reader — which is what makes the fix load-bearing rather than
   tidy.
