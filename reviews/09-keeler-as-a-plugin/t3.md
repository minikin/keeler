  The reuse branch asks whether the copy we would write is already there,

**Three findings considered and declined**, each with its reason:

- *Any `KEELER_REF:` value counts as a repin, including the unresolved
  `v@VERSION@` placeholder.* That is the rule the spec states — the
  comparison ignores the line on both sides — and the state is one the
  installer cannot produce: only a workflow copied from the template by
  hand carries the placeholder. Narrowing the rule to values that look
  like versions would invent behaviour no scenario asks for.
- *The pin may name a tag that does not exist yet* — VERSION is bumped on
  main before the tag is pushed, and an install from an unreleased
  checkout writes a pin nothing will resolve. The spec answers this
  deliberately: the fetch step "fails naming the ref and the line to
  fix", which is T12's scenario _A ref that does not resolve is named_.
- *Temp-file leaks.* The manifest-backup `EXIT` trap replaces the fetched
  tarball's, so `$tmp` leaks on every fetching install — that is
  pre-existing, and `$pinned` joins it only on a run that is already
  failing. Rearranging the trap architecture is not this task's.
