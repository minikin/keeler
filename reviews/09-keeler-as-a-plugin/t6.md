## Part 2 — generic review

Run with the built-in `code-review` skill over `HEAD~1..HEAD`. Five
findings; two fixed, one refused, two carried to the summary.

1. **`init.md` claimed the installer never fetches** — it does, whenever
   `KEELER_REF` or `KEELER_TARBALL` is set in the environment
   (`install.sh:90`), which would install a released Keeler and pin the
   workflow to a version other than the plugin doing the initialising.
   **Fixed**: the step says so and says not to set them.
2. **The wrapper check read only a span's first word** — so
   `KEELER_FAN_OUT_YES=1 just keeler-fan-out`, a line the `Justfile`
   itself prints, would have passed as wrapped. **Fixed**: no bare `just`
   anywhere in a span, and the invocation starts after any environment
   prefix. Confirmed to fail on that shape before the fix.
3. **The init flag check scanned the whole file** — `argument-hint:` in
   the frontmatter satisfied it with step 2's forwarding bullets deleted.
   **Fixed**: it reads the body, which is the part the agent follows.
   Confirmed to fail with the bullets renamed before the fix.
4. **`tasks.md` names the `Justfile` as a hot file** — the finding was
   that no adopter has one after this spec. **Refused**: an adopter may
   keep their own justfile (the spec has a scenario for exactly that),
   spec 06's `the_template_and_the_tasks_command_carry_the_format` pins
   `Justfile` as a named hot file in this very command, and the sentence
   is about the project's file, not Keeler's. The wording now says
   "the project's own `Justfile`" to remove the ambiguity.
5. **`keeler.md`, `gates.md` and `graph-mode.md` still spell every recipe
   `just <recipe>`** — a real hole, and not T6's to close. Carried to the
   summary as an open question: it needs a spec amendment, because
   `tests/plugin.rs`'s `GATES` table (T4's) pins the current spelling and
   no task in spec 09 owns the re-spelling of those three files.
