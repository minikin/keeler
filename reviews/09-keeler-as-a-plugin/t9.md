Spec conformance: T9's seven scenarios each map to a test named after it in
`tests/justfile.rs`, the file the spec designates — _A recipe runs against a
project that has no justfile_, _The project's own justfile is neither read nor
written_, _A recipe that calls another recipe calls its own Justfile_, _Every
self-call in the Justfile names its own file_, _The graph is read with the
script beside the Justfile_, _Recipe outputs name the wrapper, not a project
recipe_, _The upgrade recipe is gone_. The Implementation Notes' invariant
("every `just` token that begins a command in a recipe body is followed by
`--justfile`") is the fourth of those plus two proptest properties on the
scanner itself: a call is seen wherever a command can begin, and the word
`just` as an argument is not one.

Scope: the Justfile's self-calls, its `keeler-graph.sh` lookups, its printed
lines, `default` and `keeler-upgrade` — T9's ground exactly. Beyond the two
test files the spec names, `tests/fan_out.rs` and `tests/land.rs` needed the
same stub change: their stubs key on `$1`, which is now `--justfile`, so
without it a fixture would have handed the whole gate to the real `just` and
run it for real. `tests/spawn.rs`'s no-tmux fixture gained a `just` symlink for
the same reason — `just` stopped being optional the moment the recipes started
reaching each other through it. T9's box is left for /keeler:mutants.

Findings settled in this review (fixed at the commit above):

- The self-call scan was blind to `just`'s own line prefixes. `default`'s
  `@just … --list` — the one non-shebang self-call in the file — was invisible
  to the guard, so the very recipe the task changed was unguarded, and a future
  `@just dev` would have passed both the acceptance test and the property while
  shipping the bare call. `is_command_start` now treats a prefix of `@` and `-`
  as a place a command begins, the word-boundary test admits those characters,
  and `COMMAND_STARTS` samples all three spellings. Verified by reintroducing
  `@just --list` and watching the guard name `default` line 3.
- `recipe_header` tested `head.contains(":=")` after `split_once(':')` had
  already thrown the `=` away — a condition that could never be true, so a
  `set shell := […]` line would have registered a recipe named `set`. The test
  is now on the tail, where the `=` actually is.

Findings noted and left open:

- `Justfile:548` — the runner's death-check still reads
  `$root/scripts/keeler-graph.sh`, the main checkout's parser, while every
  other call site moved to `{{justfile_directory()}}`. Deliberate: the spec
  gives `_write-runner` to T11 ("after T9 has been through it") and pins this
  line with T11's own scenario, _The runner reads the graph with the plugin's
  parser_. Taking it here would leave that scenario green before its task ran.
- `Justfile:568` — the runner's gate now names the spawning checkout's
  Justfile rather than the worktree's own, so a task branch that changes a
  recipe is not gated by its change. That is the plugin's semantics and not an
  accident: the plugin is one directory, `keeler keeler-branch` (T11's
  spelling of this line) resolves through `bin/keeler` to that same single
  file, and a per-worktree Justfile is exactly what this spec removes.
