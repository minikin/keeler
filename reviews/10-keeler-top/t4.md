The task's stated deliverables all landed: the `keeler-status` parser
(`status.rs`), the `keeler-graph.sh` parser and the graph read
(`graph.rs`), the `git show <ref>:<rel>` temp-file read and `BranchFacts`
(`git.rs`), and the `Dispatch` trait whose `Shell` shells through the
plugin's own Justfile (`dispatch.rs`).

Two of those have no scenario of their own in T4, and are unit- and
property-tested rather than driven through a frame that does not exist
yet. The `keeler-status` parser's scenarios are T5's — the state column,
the header, the dashes — so what is pinned here is the format itself: a
round-trip property against the recipe's own `printf`, generating the
vocabulary the recipe can actually print and paths with spaces in them,
because the markers and not the columns are what tell the fields apart.
And `BranchFacts` carries the branch's commits, which only T5's detail
pane renders; the spec's data flow puts that `git log` in this task's
per-worktree read, so it is gathered here and asserted here.

**Four findings from the generic review, all four acted on. One of them
was right for a reason different from the one given, and the difference
mattered.**

**`just` was called without `-q`, so every relayed refusal carried just's
own line on top of the recipe's sentence.** True, and `keeler-spawn`
already passes `-q` to its preflight with a comment saying why. But the
first fixture written for it — a linewise recipe echoing to stderr —
failed under `-q` with *nothing* relayed at all, which reads as an
argument against the fix. It is not: `just -q` gives a linewise recipe a
null stdout *and* stderr, and leaves a shebang recipe's two streams
alone. `keeler-status` carries a shebang, as every graph-mode recipe
does, so the board gets the sentence and not the report. The fixture
recipes in both tests were rewritten with shebangs to match the thing
they stand in for, and
`a_recipes_refusal_reaches_the_board_without_justs_report_of_it` pins the
relay. Had the fixture been left linewise, a correct board would have
looked broken and a broken one — no `-q`, noisy refusals — would have
looked right.

**`git status --porcelain` obeys `status.showUntrackedFiles`.** On a
machine that sets it to `no`, a worktree whose only uncommitted work is
new files reported clean — wrong in the direction that gets work thrown
away, since a `0 dirty` column is what says a branch is safe to remove.
`--untracked-files=normal` asks for git's default explicitly, and
`a_repository_that_hides_untracked_files_still_has_them_counted` sets the
config and counts the file.

**The two head-hash assertions were the machine's to fail.** The fixture
runs git with `GIT_CONFIG_GLOBAL=/dev/null` and the board must not, so a
`core.abbrev = 12` in someone's `~/.gitconfig` had the test compare a
twelve-character hash against a seven-character expectation. Both now
assert the head is a prefix of the full hash and at least seven
characters long, which is what "the branch's head" means without pinning
a length nobody promised.

**`create_dir_all` adopts whatever is at the path.** The spec copy's
directory is `<temp>/keeler-top-<pid>-<serial>`, which is predictable,
and on a shared `/tmp` adopting it means writing into — and, on drop,
removing — a directory somebody else made. `create_dir` refuses instead;
a tick that refuses is a tick, and the next one has the next serial. The
shell this mirrors reaches for `mktemp -d` for the same reason.

**The mutation gate found the hole that fix opened.** `next_serial`
replaced by a constant survived the first run twice, over 38 mutants:
nothing failed when every copy shared a name, because no test ever had
two alive at once. `two_copies_alive_at_once_do_not_share_a_directory` is
that test, and it is the stronger claim — with `create_dir` a shared
serial refuses the second read outright, and the first copy's drop takes
the second's file. The re-run found no survivors, and the branch gate's
own run reported 60 mutants over the branch: 47 caught, 13 unviable,
none surviving.

**One thing deferred, deliberately.** `Dispatch` carries only the two
reads. `Pause`, `Resume` and `Attach` are T7's, and a trait with methods
nothing calls would be implementing ahead of the tests; T7 widens it, and
the recording double the crate's Implementation Notes describe arrives
with the task that needs one.
