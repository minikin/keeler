## Four things that reach past T6's scenarios, and why

- **Ctrl-C quits, beside `q`.** Raw mode is what makes this necessary: the
  terminal no longer turns the keystroke into a signal, so without the arm a
  board would be the one program the most universal way of leaving anything
  does not leave. One match arm.
- **The arrows move the selection as `j`/`k` do.** Conventional, one arm
  each, and pinned by its own test.
- **`Dispatch` gained `Send + Sync`.** The status read runs on a thread;
  every implementation already met the bound.
- **`mutants` is a new dev-dependency.** See the mutation section below.
  It is the one dependency this task added and it never reaches an adopter's
  build.

If any of the four should not stand, they are the places to look; none of
them changes a scenario's answer.

## The generic review: seven findings, all seven acted on

The change is two new modules of seams between a pure core and the real
terminal, and every finding was in a seam.

**A resize was a tick.** `press` turned every non-key event into the same
`None` the timeout gives, and `step` read that as the second passing. A
tick is a `git show`, a `bash` and four `git` calls per task, so dragging a
window edge across the board ran all of it dozens of times a second — while
`press`'s own doc comment promised only a frame. `Woke` tells the three
apart now: a key, something else the terminal sent, and nothing at all.

**And a key was never a tick.** The tick fired only when the wait ran out,
so a finger held on `j` — which wakes the loop every few milliseconds —
froze the columns for as long as it was held. `tick_due` is the wait
running out *or* a second since the last tick, which covers the resize
storm too: the board slows down under one, it does not stop.

**A refusal outlived what it was about.** `adopt` carried `board.message`
forward and nothing ever cleared it, so one `git show` that lost a race, or
a spec uncommitted for a second during a rebase, left a sentence under the
table for the rest of the session. Each read owns its own now and takes it
away when it stops refusing. Two of them, not one line written over by
whichever spoke last: the reads are five seconds apart, so a graph refusal
in one line would be wiped by the report arriving, and a report refusal by
the tick a second later. The report's is shown first, being the slower read.

**A refusal was asked again on the very next pass.** `answered` is the age
of the last *report* and a refusal is not one, so a cadence measured from it
found the answer five seconds stale on every pass and spawned a `just` a
second at a machine that had just said it could not answer — precisely what
`status_due`'s own comment says it prevents. The feed keeps its own clock,
moved on every answer whatever it says; the header keeps the report's, so
the age it shows stays honest while the reads keep failing.

**The cursor came back invisible.** `Terminal::draw` hides it on every frame
that sets no position, and this board sets none; leaving the alternate
screen restores where the cursor is and not whether it can be seen. `q` was
handing back a shell whose prompt had no cursor in front of it. `restore`
sends `Show`.

**A read that died took the screen with it.** The panic hook is
process-wide and the guard is the board's thread's, so a panic on the
`keeler-status` thread — a case `take()`'s `Disconnected` arm exists for —
restored the terminal from under a board that was still drawing on it. The
hook restores for the thread that installed it and no other; a message from
elsewhere belongs on the board that is still up.

**And the screen was given back twice.** On a panic the hook restored and
then the unwinding `Guard::drop` restored again, and `ESC[?1049l` sent twice
is not idempotent: the second one puts the cursor back where the entry saved
it, which is above the message the first one made room for. One flag both
consult — whichever runs first is the one that runs, and the acceptance test
reads `enter, restored, printed` with no second `leave`.

Two tests were added that are not scenarios, and are marked as such in the
file: _a window being dragged is frames and not ticks_, and _a tick that
could read the graph takes its word and its refusal back_. The second
exists because every other fixture in this suite stands outside a
repository, where the graph read refuses — the succeeding path had never
run.

## The mutation gate: six functions declared out of its reach

The first `mutants-diff` left seven survivors and three timeouts.

The three timeouts were the tests' own fault and are fixed: two spun on
`feed.take()` in an unbounded loop, which a mutated `ask` or `take` turned
into a hang, and the third asserted through a held `MutexGuard` into a panic
hook that locks the same list — a deadlock where a test failure should be.
The loops are bounded and the lists are read out before anything is asserted
about them.

One survivor was a real gap: `Surface::draw` replaced by `Ok(())` survived,
because the tests rendered the board themselves rather than reading back
what a pass had drawn. `lines_of` reads the terminal the passes drew on, so
a `draw` that draws nothing no longer reads like one that drew the right
thing.

The other six are `Tty::enter`, `Tty::leave`, `restore`, `Keys::next`,
`waited` and `run`, and they carry `#[cfg_attr(test, mutants::skip)]` with
the reason beside each. Raw mode rewrites the termios of a real terminal
and crossterm reads the keyboard from the controlling one; under nextest
every test is a process whose stdout is a pipe and which has neither. What
the gate would replace each with is `Ok(())` or `Ok(None)`, which no test
could tell from the truth. **The decisions were moved out rather than
excused** — `woke_of` is what `Keys::next` used to decide and is a function
of an `Option<&Event>`; `restore`'s order is `Guard`'s and `Guard` is tested
against a recording screen; `run` composes `looping`, `Guard` and
`restore_on_panic`, each of which is tested. The attribute resolves to the
`mutants` crate, a dev-dependency: an empty macro, never built into the
binary an adopter runs.

`Keys::next` then failed CRAP at 20 — complexity 4, coverage 0 — which is
the same fact arriving through a different gate, and the same fix answers
it: the `match` moved into `woke_of` and the call is one line.

## The cost T5's review left to this task, and where it now stands

T5 recorded that `Board::assemble` runs four `git` queries per task per tick
and left it to T6, "where the second hand starts". It stands, deliberately:
it is the spec's own data flow — step 3 of "Every second" lists all four —
and this task's two tick findings are about how *often* that runs, not what
it does. Ten tasks is forty subprocesses a second on a board nobody is
touching, and the commit list from the fourth query is read for the selected
row alone. Narrowing it is a change to an approved design and belongs to
whoever can approve one.
