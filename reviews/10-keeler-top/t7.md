The task's stated deliverables all landed: `Pause`, `Resume` and `Attach`
as actions carried out through `Dispatch`, kill-then-mark, `switch-client`
inside tmux, and the guard dropped and re-entered around the attach.

**Where the two names come from.** `keeler-status` composes the session as
`keeler-<slug>-<tid>` and the marker as `<runs>/<tid>.paused`; the board
composes the same two from the report it was given — the slug from the
path in the report's header, the marker beside the log the report named.
Not from `--root`: the recipe hands the binary `$(pwd -P)`, which is not
the repository root when somebody opens the board from a subdirectory, and
a marker written under a run directory composed from it would land where
nothing reads it.

**How the guard reaches the attach.** `step` already had the surface, so
the guard went into it: `Live` holds the screen and the buffer together and
`Surface` grew `away`. Two things needed both halves — tmux wants the
terminal, which is the guard's, and the frame after it is drawn by
difference against a frame tmux has written all over, which is the
buffer's. `Live::away` gives the screen back, runs tmux, takes it again and
clears; a `Terminal` holding no screen of its own has nothing to give back
and still clears.

## The generic review: four findings, all four acted on

**A lever's answer was gone within the second.** `pause` and `resume` wrote
`board.message`, and every tick re-assembles the board from the two reads'
sentences — so a `keeler-resume` refusal was drawn once and blanked a
second later. `p` and `R` are pressed exactly when something is going
wrong, and a refusal nobody can read is not one. A keypress now owns a
sentence of its own beside the two reads', shown before either of them,
cleared by the next keypress and by nothing else. Two acceptance scenarios
and one unit test now tick after the lever and assert the answer is still
there.

**`R` freezes the board for as long as the recipe runs.** True, and it
stands: `keeler-resume` is a `just` that runs a second `just` plus a graph
read and a `tmux new-session`, all on the thread that draws. What the
review changed is that the board says so — `keeler-top: resuming T1…` is
set *and drawn* before the recipe starts, so the still board is explained
rather than merely still. It is not threaded because the spec's own data
flow threads exactly one read, the one that runs on a cadence: a lever is a
keypress somebody is waiting on, the board has nothing else to draw
meanwhile, and a threaded resume brings a second `R` while one is out, an
answer arriving into a board that has moved on, and no scenario asking for
any of it. **This is the one accepted cost in T7, and it is the place to
look if the board feels stuck after `R`.**

**Ctrl-P killed an agent.** `KeyCode::Char('p')` had no modifier guard,
while the Ctrl-C arm above it proves modifiers reach `on_key`. The three
levers now carry `if plain(key)` — shift aside, which is how `R` is typed
at all.

**A screen half taken was left that way.** If `enter` fails on the way back
from an attach, `IN_SCREEN` is already false, so neither `Drop` nor the
panic hook restores — and `Tty::enter` is raw mode *then* the alternate
screen, so a failure between the two leaves a shell that no longer echoes
what is typed into it. `away` now leaves once more on that path.

The reviewer found nothing wrong with the kill-then-mark ordering, the
`switch-client`/`attach` split, the `=`-exact session naming or the
back-buffer reset, and confirmed the three composed names against the
shipped recipes.

## What the gate found before the review did

`just cov` put `dispatch.rs` at 89.16% lines against a bar of 90:
`Shell::kill`, `Shell::resume` and `Shell::attach` were the three functions
no test reached, each of them running the one program a suite may not run.
Two tests close it without pretending. A session nobody started can be
killed, switched to and attached to on any machine — the answer is tmux's
refusal where tmux is installed and "not installed" where it is not, and
all three levers have to give back one or the other, since a board that
reported success would write the paused marker for a kill that killed
nothing. And the resume is run for real against a stub Justfile, the way T4
runs `keeler-status`: an argv assertion alone cannot tell a board that
composed the right command from one that ran something else.

`Shell::in_tmux` carries `#[cfg_attr(test, mutants::skip)]` and is the
seventh function in this crate to. Setting an environment variable is a
process-wide, unsafe act in this edition and the suite runs its tests in
threads, so neither answer can be arranged; the decision it feeds is
`inside_tmux`, a function of the variable, tested against both.
