## Findings (left open, for the user)

4. **`keeler-spawn` clears a stale verdict but not a stale marker.**
   `Justfile:812` does `rm -f "$exit_file"` before writing the runner,
   for the stated reason that "a verdict left by an earlier run of this
   task is not this run's". After this task the same is true of
   `.keeler/runs/<slug>/<tid>.paused`, and nothing clears it: pause T1,
   abandon the run by hand (`git worktree remove`, `git branch -D`),
   spawn T1 again, and let the new session die — the board says `paused`
   about a run nobody paused, and offers to resume a session that was
   never stopped.

   Not fixed, because the spec answered this case differently and on
   purpose: "A marker nobody resumes — the human removed the worktree by
   hand — would say `paused` for ever, so `keeler-status` prints beside a
   `paused` line the same escape hatch it prints for `failed`: the `rm`
   that clears it." That escape hatch is implemented and tested, so the
   task is never wedged; what is wrong is only the word, until the human
   runs the `rm` the board names. Widening the change to a fourth
   Justfile region — one T8 does not name and the Implementation Notes
   count as "three touches" — is a spec amendment, so it is proposed
   rather than taken: **add `rm -f "$runs/$tid.paused"` beside
   `rm -f "$exit_file"` in `keeler-spawn`**, with an acceptance test for
   a re-spawned task that starts unpaused.

5. **`tests/spawn.rs` needed no change.** T8's line anticipates it being
   "updated where the new word appears", and nothing there asserts on
   anything that moved: every `died` case in that file is a run with no
   marker, and all 480 tests pass untouched. Recorded so the unticked
   half of the task line is a finding rather than an omission.
