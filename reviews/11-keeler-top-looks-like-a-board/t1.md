## Deviations from the Implementation Notes, and why

**`bar()` returns a `Bar`, not `(String, Style)`.** The sketch's pair
cannot express the scenario beside it — *the context bar fills cells and
colours by threshold* ends "and the empty cells chrome" — and a caller
handed one string and one style writes `Span::styled(bar, style)`, which
paints the whole bar red at 84%. The struct hands over the two halves and
the style each is drawn in, so the misuse is not reachable. Notes are
notes; the scenario is the law.

**`Theme::chosen` takes four variables, not three.** `LC_ALL` and `LANG`
arrive separately so the precedence between them — LC_ALL wins when set to
something, an exported empty one stands aside — is a decision a test can
reach. `from_env` is left with four `var_os` calls and no decision at all.

## The generic review: four findings, all acted on

Run through the built-in `code-review` skill at high effort over

   Test: `the_track_is_chrome_at_every_share_and_the_fill_never_paints_it`.

   `Option::or_else` does not fall through on `Some("")`, so

4. **The `from_env` test reproduced the function's body**, and reduced to a
