## The six spec-10 tests this frame changes

The spec's *What this supersedes* section names them, and each is moved
onto `--once` or rewritten here rather than deleted:

- **every task in the graph has a row, in spec order** — now asserted
  against `frame::once`, which is the surface where spec order still holds.
- **a done task with no worktree shows dashes for the live columns** —
  already asked through `cells()`, which is `--once`'s composition;
  untouched.
- **a landed feature whose branch is gone still renders** — the frame's
  rows are asserted to carry the state and *no* dash; `--once`'s commit
  column is still `—`.
- **a narrow terminal drops the detail pane before it drops columns** —
  the same scenario at 100×16 rather than 100×12, because five running
  tasks are eleven lines now and were six. It still asserts what it was
  about: every row whole, no clipped column, no pane.
- **a long command is cut to the column with an ellipsis** — the cut is
  `--once`'s TOOL column and, in the frame, the second line: asserted at
  120 columns to be drawn whole and at 80 to be cut.
- **the commit column** — `N dirty` in `--once`, `~N` in the frame, both
  asserted.

Three loop tests of spec 10 (`the_stream_is_re_read_once_a_second…`,
`a_slow_keeler_status_does_not_stall_the_board`,
`enter_attaches_to_the_selected_running_task…`) read the tool out of the
row; they now read it off the line under the row, through a `under_of`

## Deviations from the Implementation Notes, and why

**`lines()` takes `now`.** The sketch is `lines(row, cols, theme,
selected, compact)`. The second line carries the elapsed at the panel's
inner right edge, and the elapsed is a difference against a clock; a
renderer that read `Timestamp::now()` itself would be untestable at the
one place the scenario pins.

**`graph::read` answers with a `Graph`, not a `Vec<GraphLine>` and a
string beside it.** The notes say it "returns the spec text alongside the
states". One value rather than two because it is one read: the script's
lines and the titles come from the same copy of the same spec at the same
ref, and a caller free to pair them differently could show a title from
one commit beside a state from another. `App` and `Board::assemble` take
that value.

**The rows are composed for the panel's inner width before the panel
exists.** Every offset in the spec's column table is measured from the
panel's inner left edge, and the scenario says a row at 120 columns is 118
cells. So `render` lays the table out at `width - 2` and draws it at
`x + 1` — the two cells T4's borders will take. The frame in this build has
no box around that table yet, and the header, the detail pane and the
message line are still at column 0 where spec 10 left them: T4 is where
they become panels.

**`compact` is implemented, not just accepted.** The parameter is in the
notes' signature, and what it means — the second line goes, and a live
row's tool moves into the title column — is the row's own composition.
*When* it is turned on is T5's: nothing in this build ever passes `true`
except the unit test that pins the behaviour.

## What is here that no T2 scenario names

- **`Board::moved`, and `j`/`k` reading it.** Ordering by group is what
  this task added, and it broke the selection: with a done T1 and a running
  T2, `j` moved the marker *up* the screen, because `on_key` walked the
  report's order while the rows drew in the board's. `j`/`k` are T5's line
  in the spec, but the regression is T2's making, so it is fixed here and
  T5 inherits a board whose selection already walks the drawn order. The
  answer is still a report index — the levers and the pane read that.
- **`Row::live` and `board::PAUSED`/`DONE`.** Which rows carry a second
  line, and what makes a board a finished one. Both are read by the frame
  in this task.

## The generic review: four findings, all acted on

Run through the built-in `code-review` skill at high effort over
`e059b41..HEAD`.

1. **The selection walked the wrong order.** Real, and described above.
   Test: `board::tests::the_selection_moves_down_the_board_as_it_is_drawn`.
2. **A paused row's second line grew a clock.** Real: `under()` appended
   the elapsed for every live row, so `resume: R` was followed by the
   timer of the tool call the kill interrupted — a wait nobody is in,
   ticking forever. The acceptance fixture had `run: None` and could not
   have caught it; the test now carries the outstanding call a real paused
   report has. Fixed: the elapsed belongs to the running row alone.
3. **The column headings cut with a literal `…`.** Real: `Columns::header`
   went through `left`/`right`, which hardcoded U+2026, so under
   `KEELER_TOP_ASCII=1` a narrow board would have put the one glyph that
   theme exists to avoid above rows cutting with `...`. `header` takes the
   mark now. Test:
   `layout::tests::the_header_is_cut_with_the_mark_the_terminal_can_draw`.
4. **A stale test comment** about `layout`'s second argument, which became
   a line count. Rewritten, and the assertion beside it moved to the
   threshold it now describes.

Nothing was left open.

## The two gates after it: one CRAP regression, five mutants

**`crap-delta` refused one function.** `table` was a one-line composition
and grew a loop, taking it from 1.0 to 2.0 at unchanged coverage. The
heading and the rows are two things and the loop is the rows': `frame::rows`
is its own function now, and `table` is a composition again.

**`mutants-diff` found five survivors** over the branch's whole diff — 155
mutants, which is what `just mutants-diff <branch base>` measures. The
recipe's default measures the working tree against `HEAD`, so on a branch
whose work is already committed it would have measured the uncommitted
remainder; the base was named explicitly, and the final `keeler-branch` run
on a clean tree measured 219 and caught them all.

Four survivors were tests too narrow, and one was the code's:

1. **`Row::live` → `true`, and its `==` → `!=`.** Only ever asked about a
   running row. `only_a_live_rows_tool_takes_the_place_of_its_title` asks
   it about a running, a paused and two closed tasks.
2. **`said`'s `&&` → `||`.** Would have put `--once`'s dash back in the
   frame — the one answer the two surfaces deliberately differ on.
   `a_live_row_that_has_nothing_to_say_underneath_says_nothing` now reads
   the whole row.
3. **The commit column's `dirty > 0` → `>= 0`.** No test had a clean
   worktree. `the_commit_column_names_the_dirt_only_when_there_is_some`
   does.
4. **`render`'s drawing rectangle lost its width and nothing changed.**
   The code's, not the tests': the rows were composed for one width and
   drawn on a rectangle that took its width from elsewhere, and the two
   agreed for as long as the difference was slack. One binding feeds both
   now, and the mutant is caught by the row that has to be exactly 118
   cells wide.
